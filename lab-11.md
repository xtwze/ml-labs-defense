# Лабораторная 11. Инструменты, LLM-агент и LangGraph

[К оглавлению](README.md)

Смысл: модель выбирает действия через tool_calls, программа выполняет функции и возвращает результаты модели для следующего решения или итогового ответа.

## Вопросы из обсуждения защиты

### @tool — как это называется?
Это декоратор Python. В LangChain он оформляет функцию как инструмент со схемой входных аргументов и описанием. Аннотации типов и docstring помогают построить эту схему.

### Функции оформили и сложили в список. Что дальше?
Связываем их схемы с клиентом: `llm_with_tools = llm.bind_tools(TOOLS)`. Затем вызываем `llm_with_tools.invoke(messages)`. Конкретный клиент должен поддерживать tool calling.

### Что такое bind_tools? Это метод библиотеки?
Да, метод соответствующего chat model клиента LangChain. Он готовит конфигурацию передачи описаний инструментов модели при запросе. Это не вызов самих Python-функций.

### Как LLM понимает, какой инструмент выбрать?
По сообщениям диалога и переданным схемам инструментов: имени, описанию, аргументам. Модель генерирует имя и аргументы в tool call. Доступность инструмента не гарантирует правильный выбор.

### Что будет в response = llm_with_tools.invoke(messages)?
Обычно AIMessage. В content может быть текст, в tool_calls — список запросов на вызов инструментов с name, args и id. Это не сама Python-функция и не обязательно только список инструментов.

### Где именно вызываются tools?
`selected_tool = TOOLS_BY_NAME[call['name']]` выбирает зарегистрированный объект; `result = selected_tool.invoke(call['args'])` выполняет инструмент. Выбирает имя модель, запускает функцию программа.

### Как после вызова функции получается окончательный ответ?
Результат упаковываем в ToolMessage с tool_call_id исходного вызова, добавляем в messages и снова вызываем LLM. Модель видит результат и либо просит следующий инструмент, либо возвращает итоговый текст.

```python
response = llm_with_tools.invoke(messages)  # Решение модели.
messages.append(response)                 # Сохраняем запросы инструментов.
if not response.tool_calls:
    return response.content              # Итоговый текст.
for call in response.tool_calls:
    tool = TOOLS_BY_NAME[call['name']]     # Берём зарегистрированный инструмент.
    result = tool.invoke(call['args'])    # Python выполняет функцию.
    messages.append(ToolMessage(
        content=json.dumps(result, ensure_ascii=False),
        tool_call_id=call['id']))          # Связываем результат с запросом.
# Затем следующий проход цикла снова обращается к модели.
```

### Почему детерминированный if — не то же самое?
В коде check_keywords.invoke → if → search_article.invoke → send_email.invoke последовательность выбирает программист. Чтобы модель выбирала следующий инструмент, нужен цикл model → tool_calls → выполнение → ToolMessage → model.

### Какие два способа реализации агента?
В нашем обсуждении: ручной цикл и граф LangGraph. Ручной: bind_tools → invoke → выполнить tools → ToolMessage → повторить. Граф: узел agent вызывает модель → условное ребро выбирает tools или END → узел tools выполняет → возвращаемся agent.

### Какие ещё есть методы кроме invoke?
В зависимости от объекта: ainvoke — асинхронный вызов, stream/astream — поток, batch/abatch — пакет. `.func` у некоторых инструментов даёт исходную функцию, но это обход части обёртки; не каждый объект имеет все эти методы.

### Что неправильно в if not 7?
Число 7 истинно, поэтому not 7 всегда False. Для остановки нужно проверять `if not response.tool_calls`, иначе финальный ответ не будет корректно возвращён по этому условию.

### Зачем рисовать LangGraph?
Чтобы показать управление потоком: START → agent; если есть tool_calls → tools → agent; иначе END. На схеме должны быть и обратное ребро, и условие завершения.

## Дополнительные вопросы для подготовки

### Письмо действительно отправлено?
Если инструмент сохраняет .eml, создан файл письма. Внешняя доставка требует SMTP или другого сервиса и отдельного подтверждённого результата отправки. Нельзя считать сохранение файла доставкой.

### Зачем лимит шагов?
Чтобы ограничить зацикливание, стоимость и повторные действия. Реальные побочные действия дополнительно требуют валидации аргументов и защиты от повторов.
